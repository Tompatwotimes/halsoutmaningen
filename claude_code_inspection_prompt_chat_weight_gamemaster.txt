C. NEW FEATURE: SHARED CHAT
==================================================

The future implementation should contain ONE shared chat room.

Requirements:

- all participants can read it
- all participants can write to it
- text only in v1
- no image messages
- no reactions
- no threads
- no DMs
- no user editing
- no user deletion
- no push notifications
- complete chat history must be retained for the entire challenge
- every message stores exact date and time
- UI should show date separators
- UI should show message timestamps
- real-time message delivery
- older messages should load incrementally when scrolling upward
- read state must be tracked per user
- unread count must be tracked per user

CHAT UI:

Chat must NOT be a separate main page or navigation tab.

It should be a floating chat bubble in the bottom-right corner on the existing application pages.

On mobile:
- open as a large overlay / bottom sheet / near-fullscreen panel
- keyboard behavior must be usable and stable

On desktop:
- open as a smaller floating chat window

GAME MASTER IN CHAT:

Game Master must be able to read:

- the full chat message text
- sender
- exact timestamp
- relevant chat metadata
- relevant previous chat history

Game Master is NOT an AI or LLM.

It must remain the existing rule-based Game Master engine.

There must be:
- no LLM
- no AI chatbot
- no semantic AI interpretation of free text

Simple rule-based text triggers may later exist, for example:

- @gm
- specific words
- specific phrases
- specific participant names

A new chat message should be able to create an event such as:

chat_message_created

That event should enter the EXISTING Game Master pipeline.

The existing Game Master should then be able to select:

- Silence
OR
- one eligible Game Master effect

Game Master must also be able to post messages into the shared chat.

Game Master chat messages must:

- be stored in the same chat history
- be clearly identified as GAME MASTER
- have normal date/time metadata
- count as unread chat messages for participants

Chat must also be a possible OUTPUT CHANNEL for existing Game Master events.

Example:

→ existing Game Master candidate system
→ selected effect may be post_to_chat

CRITICAL RULE:

ONE event may produce at most ONE Game Master effect.

For example:

must NOT produce:
- one existing surprise
AND
- one Game Master chat message

for the same event.

Chat output must be one possible effect among the existing Game Master effects.

D. NEW FEATURE: WEIGHT TRACKING
==================================================

Weight tracking must be completely independent from training registration.

Users must NOT need to know or enter their weight while logging a training session.

Weight belongs under Profile.

There should be two separate concepts:

1. START WEIGHT
2. REGULAR WEIGHT LOGGING

==================================================
E. START WEIGHT
==================================================

Start weight is separate from normal weight entries.

Requirements:

- participant enters their own start weight
- the first time it is saved, a 24-hour edit window begins
- participant may freely modify the start weight during those first 24 hours
- after exactly 24 hours, it becomes locked for the participant
- participant must not be able to unlock it
- admin must be able to correct a locked start weight

Admin corrections must be audit logged.

Audit data should include at minimum:

- previous value
- new value
- timestamp
- admin/user who performed the change

Assess how this should fit the existing admin architecture.

==================================================
F. REGULAR WEIGHT LOGGING
==================================================

Regular weight logging is optional.

Requirements:

- no daily requirement
- participant may log weight every day if they want
- weight can ONLY be entered for the current calendar day
- NO backdating
- maximum one official weight entry per participant per calendar day
- today's entry may be edited during the same calendar day
- once the calendar day has passed, the participant may no longer modify it

Do not tie this functionality to training logs.

Do not introduce mandatory weight images or proof unless such functionality already exists and is explicitly reusable.

==================================================
G. HIDE MY WEIGHT
==================================================

Default behavior:

Weight data is visible to all participants.

A participant must be able to enable:

"Hide my weight"

When enabled, ALL of that participant's weight information must disappear for other participants.

That includes:

- start weight
- latest weight
- absolute kg change
- percentage change
- ranking position
- all previous weight entries
- all dates
- the full weight history
- the weight chart

The hiding behavior is RETROACTIVE.

If a participant has had public weight data for three weeks and then enables "Hide my weight":

all previously visible weight data must immediately become unavailable to other participants.

If they later disable hiding:

the historical data becomes visible again.

The participant must always be able to see their own data.

Admin must be able to see it.

Game Master must be able to access it internally.

CRITICAL PRIVACY RULE:

Game Master may use hidden weight data internally in its rule engine.

However, it must NEVER publicly disclose hidden weight information through:

- chat
- roast
- surprise
- banner
- notification
- other public Game Master output

This includes:

- exact kilograms
- percentage change
- trend
- ranking
- indirect wording that reveals or strongly implies the person's hidden weight progress

Inspect how this kind of output-safety restriction can be enforced centrally rather than relying on every individual template author to remember it.

==================================================
H. PUBLIC WEIGHT RANKING
==================================================

There should be a public weight-loss ranking during the challenge.

Ranking is based on the percentage difference between:

LOCKED START WEIGHT

and

LATEST REGISTERED WEIGHT

Formula:

percentage_change =
(latest_weight - start_weight) / start_weight * 100

Example:

start_weight = 82.0
latest_weight = 78.7

percentage_change ≈ -4.02%

A lower / more negative percentage means greater weight loss.

People with "Hide my weight" enabled must NOT appear in the public ranking at all.

For participants with public weight data, other participants should be able to see everything:

- start weight
- latest weight
- kg change
- percentage change
- complete weight history
- dates of all weigh-ins
- full weight chart

The ranking always compares start weight to the participant's latest registered weight.

It does NOT matter how old the latest entry is.

The latest registered entry remains the current ranking value until a new one is logged.

==================================================
I. FINAL WEIGH-IN
==================================================

The official final weigh-in will happen physically, in person, when all participants are together at the finale.

A participant who has hidden their weight throughout the challenge is still fully eligible to win the weight-loss competition.

The privacy setting only controls public visibility during the challenge.

It must not remove the person from the actual competition logic.
