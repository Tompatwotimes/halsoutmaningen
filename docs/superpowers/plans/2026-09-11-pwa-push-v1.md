# Implementation plan — PWA + Web Push Notifications V1

Spec: `docs/superpowers/specs/2026-09-11-pwa-push-v1-design.md`. Branch: `feat/pwa-push-v1`.

## Task 1 — Schema + RLS
`supabase/migrations/20260911090000_notifications_schema.sql`: `challenges.push_enabled`, `push_subscriptions`, `notification_preferences`, `notification_outbox`, `notification_deliveries`, `_daily_first_completion_claims`. RLS: owner-only for the first two; no client SELECT on the queue tables. Widen `audit_log` entity vocabulary if a moderation-style audit is needed (not required here — no admin-editable content).

## Task 2 — Preference/subscription RPCs
`supabase/migrations/20260911090100_notifications_rpcs.sql`: `register_push_subscription(endpoint, p256dh, auth_key, user_agent)`, `unregister_push_subscription(endpoint)`, `get_notification_preferences(challenge_id)`, `update_notification_preferences(challenge_id, ...booleans)`. All `SECURITY DEFINER`, owner-scoped via `auth.uid()`.

## Task 3 — Producer triggers
`supabase/migrations/20260911090200_notifications_producers.sql`: chat reply/like/all-message triggers, Straffbanken hook (extend `assign_penalty`), GM hook (`push_enabled` column + `AFTER INSERT` trigger on `game_master_events`), training first-completion trigger + claim table, personal-status hooks on retroactive approve/reject. Every hook is a pure additive `insert ... on conflict do nothing`.

## Task 4 — Scheduler + cron
`supabase/migrations/20260911090300_notifications_scheduler.sql`: `_notification_scheduler_tick()`, guarded `pg_cron` registration (hourly), copying the exception-swallowing pattern from `_game_master_tick_all`'s registration block.

## Task 5 — pgTAP
`supabase/tests/0031_notifications_schema_rls.test.sql`, `0032_notifications_producers.test.sql`, `0033_notifications_scheduler.test.sql`. Run locally impossible (no Docker) — validated via `database-tests.yml` CI on the PR.

## Task 6 — Edge Function
`supabase/functions/notification-dispatcher/index.ts` + `deno.json` entry reuse. Actions: `dispatch` (claim+send loop), `self-test` (one push to the caller). Uses `npm:web-push@3`. Shares `_shared/cors.ts`.

## Task 7 — Frontend PWA shell
- `public/manifest.webmanifest`: real icons (generate from an updated brand SVG via `sharp`, install as a throwaway devDependency with `--no-save` or a scratch script — never commit a new prod dependency for a one-time asset generation).
- `public/sw.js`: minimal, no caching, `push` + `notificationclick` handlers.
- `src/main.tsx`: register the service worker.
- `src/features/push/`: subscribe/unsubscribe, preference hooks.
- `src/features/pwa/`: install-prompt capture, iOS instructions.

## Task 8 — Profile UI
`src/pages/ProfilePage.tsx`: new "Notiser" card — install affordance, permission state, per-category toggles, self-test button.

## Task 9 — Logout cleanup
Wire `unregister_push_subscription` + `PushSubscription.unsubscribe()` into the existing sign-out path.

## Task 10 — Frontend tests
Vitest coverage for push hooks, preferences UI, iOS-instructions component, deep-link URL builder, sw.js payload-shape pure function.

## Task 11 — Deploy workflow for the dispatcher cron
`.github/workflows/notification-dispatch.yml`: scheduled (`*/5 * * * *`) `workflow_dispatch` + `schedule` calling the deployed function URL with a `CRON_SECRET` bearer.

## Task 12 — Review, PR, release
Self-review against the checklist in the original task brief. Open PR `feat/pwa-push-v1` → `main`. Merge when green. Release order: migrations → secrets → function deploy → frontend (via `deploy-production.yml`, which requires a `production` environment reviewer approval — **flag this as the one step that may require a human approval click**, not a credential blocker but a repo-configured manual gate) → GH Actions cron secret setup → smoke.
